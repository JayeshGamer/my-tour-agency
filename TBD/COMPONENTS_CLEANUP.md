What the heuristic checks
- It searches all source files under `src/` for import-like strings referencing component paths (e.g., `components/ui/button`).
- It also checks component directory `index.ts` barrels to see whether a component is re-exported and caught via directory imports.

Limitations (you must manually verify before deleting)
- Dynamic imports using template strings or computed paths may not be found by the search.
- Components referenced only from runtime data (e.g., a string used to resolve a component at runtime) will be missed.
- Test files, MDX files, or external tooling could reference components in ways the heuristic does not detect.
- A component could be kept for future use or be referenced in commented code; this scan doesn't consider intent.

Manual verification checklist (recommend doing this for each candidate):
1. Search the entire repo (including `pages`, `app`, `scripts`, `tests`, and `.mdx`) for the exact file name and for the component name (both the PascalCase and kebab-like paths). Example (in a terminal):

   - On Windows (cmd.exe):
     findstr /s /i /n "BentoTourCard" *.*

   - Or use your editor/IDE global search for the component name and file path.

2. Check `src/components/**/index.ts` barrel files — if the component is exported from an index and that index is imported elsewhere, deleting the file may break imports.
3. Inspect dynamic import usage (e.g., `await import(...)`, next/dynamic) which may reference components via variables or arrays.
4. Look for references in build scripts, seed data, or admin-only pages that may be excluded from normal site navigation.
5. Run the app and navigate to the parts of the app that might use admin or edge-case components (admin dashboard, bookings, checkout flows).

Safe deletion procedure
1. Create a new git branch for cleanup:

   git checkout -b cleanup/unused-components

2. Move (don't immediately delete) the suspected files into an `archive/` folder inside the `src/components` directory so your imports break clearly if something still depends on them. Example:

   mkdir src\components\archive
   git mv src\components\tours\BentoTourCard.tsx src\components\archive/

3. Run the dev server and your test suite (if any):

   npm run dev
   npm run test:e2e

4. If nothing breaks for a reasonable smoke test and CI passes, delete the archived files and commit. If something breaks, restore the file using `git restore` or `git mv` back to its original location.
